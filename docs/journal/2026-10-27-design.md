# Journal: design phase (2026-10-27 and 2026-10-28)

Backfilled from the design conversation when the repository was created. The decisions themselves are recorded in `docs/design/2026-10-28-cfd-agent-design.md` (sections 3, 4 and 16).

## 2026-10-27 obstacle: Azure CLI not installed on the laptop

The owner's laptop had no Azure CLI, so the subscription limits could not be inspected. It was installed, but it is not on `PATH`; all later commands call it by its full path (`C:\Program Files\Microsoft SDKs\Azure\CLI2\wbin\az.cmd`), which is also written into the project instructions.

## 2026-10-27 obstacle: `az cognitiveservices usage list` returned nothing

The model quota listing was empty because the `Microsoft.CognitiveServices` resource provider was not registered in the subscription. Registering the provider made the Foundry model quotas visible.

## 2026-10-27 obstacle: no GPU quota in Azure

Quota was 0 for every GPU VM family, and the owner's quota increase requests for Italy North and Spain Central were rejected. Compute is limited to 6 vCPU per region and 4 vCPU per VM family, so no GPU is available in Azure and the LLMs run serverless in Azure AI Foundry, paid per token.

## 2026-10-27 decision: models served serverless from Azure AI Foundry

With no GPU, hosting open-weight models on a VM was ruled out. The project uses Foundry serverless deployments, with a provider interface that lets a commercial model be swapped in by configuration.

## 2026-10-27 obstacle: `gpt-oss-20b` cannot be deployed, `gpt-oss-120b` can

Deploying `gpt-oss-20b` failed with both the `GlobalStandard` and `DeveloperTier` SKUs: Azure reported that the SKU is not supported for this model, which appears to be offered for fine-tuning only. `gpt-oss-120b` deployed in the probe resource group `rg-cfdagent-probe` (quota 5000) and answered a test call in about 2 s, so it became the primary model.

## 2026-10-27 decision: no CPU-only Ollama

Running a local model with Ollama on CPU was rejected. At most 4 vCPU are available per VM family, which is too slow for agent loops, and the owner wants laptop use kept to a minimum.

## 2026-10-28 obstacle: independent check of the design found methodology gaps

A reviewer who read the design as a prospective builder found that agents could iterate until their result matched the reference data, inflating the success rate, and that prompts would be tuned on the same tasks used for the experiments. The design was changed to blind evaluation: agents never see reference data or acceptance criteria, and a deterministic Scorer compares results only after the Critic's verdict is final. A headline metric (deterministic benchmark success rate) and a frozen release before the campaign were added.

## 2026-10-28 decision: task tiers removed

At the owner's request the "validated / experimental / out of scope" task categories were dropped. Every task is attempted with the same pipeline, prompts and tools; whether a result was compared with reference data depends only on a link from a benchmark task file, never on a classifier.

## 2026-10-28 decision: generality rule for prompts

At the owner's request, prompts, knowledge notes and tool code may contain only general CFD and OpenFOAM knowledge, never anything specific to a test case. Fixes found while debugging on the development tasks must be rephrased as general rules, and `cfd-reviewer` blocks any violation.

## 2026-10-28 decision: generality test set replaces the held-out set

The earlier held-out set of same-family variants was replaced by a generality test set of new flow types (backward-facing step, Couette or Poiseuille channel, flat plate boundary layer, optionally a heated cavity). The owner writes these tasks, and none is run before the frozen release, so nothing learned from them can flow back into prompts or code.

## 2026-10-28 decision: spending envelopes

The owner approved envelopes of up to $30 for M0-M2 and up to $45 for the M3 campaign, with a reserve of about $25 that is never spent without a separate decision. Inside an envelope VM start/stop and test runs need no per-action approval; creating or changing Azure resources and any campaign above $5 always need approval.

## 2026-10-28 milestone: design approved

The owner approved the design document `docs/design/2026-10-28-cfd-agent-design.md` as the architecture baseline (ADR-0001), on the basis of the design conversation. Repository name `cfd-agent` was settled at the same time.
