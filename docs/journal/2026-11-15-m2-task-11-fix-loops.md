# 2026-11-15 M2 Task 11: routing, passes and cross-stage fix loops

## 2026-11-15 decision: a failed stage can route the run back to an earlier stage

Implements ADR-0006 decisions 1-5 and 7. The orchestrator pipeline is now an index over its steps, and a failed stage outcome can carry a `RouteRequest` (new module `agents/routing.py` with `STAGE_ORDER` and `ROUTE_TARGETS`: planner, geometry, mesh, case_setup, analyst). The target must precede the source; the Solver Runner edits nothing, so a fix aimed at it goes to `case_setup`. With budget left (`RunLimits.max_fix_loops = 10`, design 6.5) the orchestrator records a `FixLoopRecord`, moves the canonical outputs of every stage after the target to `superseded/pass-<n>/` (for a `case_setup` target `case/constant/polyMesh` stays in place), passes the request in the target's opening message (the Planner gets it in its phase-1 message) and re-runs the target and every later stage. A route with no budget left ends the run `failed` with "fix-loop limit of 10 reached: <stage reason>"; a failed outcome without a route ends the run as in M1.

## 2026-11-15 decision: the pass number is global, and `in_place` seeds the target from its own accepted files

The pass number is the number of fix loops so far, not a per-stage count. Attempt directories of a later pass are `attempts/<stage>-p<pass>-<attempt>`, pass 0 keeps the M1 name, and the pass is also in every transcript line and `StageRecord`. Old run records without `fix_loops` or `pass_no` still load; the Scorer path and the CLI were not touched. With `repair_mode=in_place` the first attempt of the target is seeded by `Stage.seed_from_canonical` from the stage's own accepted files (`geometry.py`; `mesh.py`; the dictionaries of `case/0`, `case/constant` without `polyMesh`, and `case/system`; `post.py`, which `AnalystStage.promote` now also keeps in `analyst/post.py`), and only files that the file scope lets the agent write are seeded. In `fresh` mode nothing is seeded. `CaseSetupStage.prepare_attempt` now copies only `case/constant/polyMesh` from the canonical case in every pass, never time directories, `postProcessing/`, logs or old dictionaries.

## 2026-11-15 obstacle: the plan's order of seeding and moving outputs aside did not fit the stage loop

The plan has the orchestrator seed the target before `move_downstream_aside` runs. The stage loop, however, used to create (and wipe) its own first attempt directory, and the `prepare_attempt` of Case Setup replaced the whole attempt `case/`, so a seed would have been lost. Solution: the orchestrator creates attempt 1 of the pass, seeds it and only then moves outputs aside; `run_stage` takes it as a `SeededAttempt` and keeps it; `prepare_attempt` of Case Setup now writes only its mesh, so the seed survives. The seeded dictionaries are still judged by the unchanged gate against the mesh that is present; a test shows that a seed whose patch names do not match a rebuilt mesh fails the static check.
