# 2026-11-15 M2 Task 14: the Critic

## 2026-11-15 milestone: the Critic is the seventh agent and the last pipeline step

`agents/critic.py` with the prompt `prompts/critic.md` (ADR-0007, accepted 2026-11-14). The Critic has read-only tools (`read_file`, `list_dir`, `calculator`) and at most 12 turns, then makes one structured call that returns a `CriticVerdict`. A guard checks the reply: a success with a failed check, a send-back without an instruction, and a success together with a send-back are invalid; at most 3 attempts. A send-back becomes a Task 11 `RouteRequest` with `origin="critic"` while `critic_rounds < max_critic_rounds` (2) and the fix-loop budget (10) is left; otherwise it stays in the final verdict and the run is not failed. A Critic that gives no usable verdict (3 invalid replies, a cost or wall-clock stop, a model-service failure) leaves `critic_verdict = None` and the run goes on to the Scorer. Verified: unit suite 2597 passed (144 skipped), ruff and pre-commit clean; in the image `cfdagent:dev` the six scripted pipeline tests passed (6 of 6, about 160 s), including `test_scripted_cavity_pipeline_with_critic_success`, and the rest of the integration suite gave 249 passed and 1 skipped (about 8 min). Cost: $0 (no Azure, no live model).

## 2026-11-15 decision: the Critic reads only the canonical files of the finished pass

It sees the task, plan, boundary manifest, mesh logs and `checkMesh` report, solver summary and log, analysis and quantities. Excluded: `results/comparison.json`, `superseded/`, `benchmarks/`, the transcript and record, the case itself, and the `attempts/*` directories of every pass (an item deferred from the review of Task 11). Reason: blind evaluation and a fresh context (design 6.3); a transcript scan test shows that no reference value reaches the Critic. The end of the solver log goes into the opening message instead of a fourth tool, because `read_file` pages from the start of a file.

## 2026-11-15 decision: `critic_verdict` holds only the final verdict

A followed send-back is recorded as a fix loop and in `critic_rounds`, not as a verdict. A failed run therefore never shows the verdict of an earlier pass.

## 2026-11-15 obstacle: a tool-made `decomposeParDict` was seeded as the agent's file

The second item deferred from the review of Task 11. After a passed parallel solve, the canonical `case/system/decomposeParDict` was made by the solver tool, and `seed_from_canonical` of Case Setup copied it as if the agent had written it. The Case Setup prompt forbids writing one, and the Solver Runner would then have been bound to its number of subdomains. Solution: `TOOL_MADE_FILES` in `case_setup.py` and a `skip` argument in `Stage._seed`; a test covers it.
