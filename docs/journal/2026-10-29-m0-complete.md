# Journal: M0 complete (2026-10-29)

## 2026-10-29 obstacle: the planned VM size is not available in italynorth

The approved design named `Standard_F4s_v2` in `italynorth`. The what-if run showed `NotAvailableForSubscription` for it there, and the v7 sizes that were listed have quota 0 (checked with `az vm list-skus --all` and `az vm list-usage`). The owner decided on 2026-10-28 to place the VM, network and storage in `belgiumcentral` with `Standard_D4as_v4` (4 vCPU, 16 GB, $0.208/h); the resource group and the AI account stay in `italynorth`. Design sections 3 and 7 were updated. Alternatives considered: `Standard_F4s_v2` in `denmarkeast` ($0.27/h) and `Standard_D4s_v4` in `spaincentral` ($0.214/h).

## 2026-10-29 obstacle: no DevTestLab auto-shutdown in any allowed region

`Microsoft.DevTestLab/schedules` is not offered in any of the five allowed regions, so the daily 23:00 (Europe/Warsaw) shutdown is a systemd timer on the VM that runs the same deallocate call with `--force`. A second timer deallocates the VM after 30 consecutive idle minutes (no SSH session, no running `cfdagent`, no project container). Both use the VM's managed identity, which holds a custom role limited to reading and deallocating that one VM.

## 2026-10-29 decision: SSH open to the Internet, key only

The owner switches networks and uses a university VPN, so an NSG rule for a single source address was not workable. The owner decided that port 22 is open to any source. Compensating controls installed by cloud-init: key-only login (`PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitRootLogin no`) and `fail2ban` with an sshd jail (5 failures in 10 minutes ban for 1 hour). No other inbound port is open. Remaining risk: members of the `docker` group are effectively root, so the passphrase of the SSH key is the real control.

## 2026-10-29 milestone: infrastructure deployed and verified

The owner approved the deployment (20 resources, about $8.70 per month fixed plus $0.208/h while the VM runs) and it was applied with one subscription-scope deployment. Checks run through `az vm run-command`: cloud-init finished without errors; both timers active; the project image pulled (5.42 GB); OpenFOAM v2512 starts; `sshd -T` shows no password, keyboard-interactive or root login; the fail2ban sshd jail is active; the idle script's `--dry-run` and `--check` pass (identity token and ARM read through the VM identity). The owner logged in over SSH with their own key, and the budget `budget-cfdagent` (100 USD, four alerts, start 2026-10-01) exists.

## 2026-10-29 experiment: idle shutdown deallocated the VM on its own

After the owner's SSH test, the VM deallocated itself at about 09:21 UTC; the journal showed the idle counter climbing from 8 to 24 minutes before that. This is the live proof that the idle path (token, ARM call, role) works. The test cost about $0.10.

## 2026-10-29 milestone: the toolchain passes on the Azure VM

On the VM, with main at 034cc5e and the published image, the integration suite gave 56 passed in 72.9 s (84 s wall), including the hand-written cavity against Ghia et al. Blob upload and delete through the VM's managed identity worked, and a chat call to `gpt-oss-120b` through the same identity worked (74 prompt and 37 completion tokens). No key was used. The VM was deallocated afterwards.

## 2026-10-29 decision: two comparison models

`qwen3-32b` could not be deployed and the owner declined a replacement, so M3 compares `gpt-oss-120b` and `Llama-3.3-70B-Instruct` (see the LLM spike entry and ADR-0002). Only `gpt-oss-120b` has been called from the VM identity so far; a Llama call from the VM is still to be made before key authentication on the AI account is switched off.

## 2026-10-29 milestone: M0 closed, cleanup and spend

The probe resource group `rg-cfdagent-probe` was deleted with the owner's approval. Spend so far is about $0.50 (an estimate from VM run time, the fixed monthly items prorated and token counts; Azure usage data lags 24 to 48 hours, so the real figure is not yet known). A final whole-branch review found no blocking defects in the tools but asked for hardening before the tag: bounding-box gates that failed open on NaN, a solver negative test that never ran with OpenFOAM, and key authentication still enabled on the AI account (changed in `infra/` as code only; it takes effect with the next owner-approved redeploy). Infrastructure deviations from the design are recorded in ADR-0003.
