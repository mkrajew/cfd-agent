## 2026-11-06 decision: detached runs, retention, liveness and blind evaluation (R47-R53)

A detached run needs its run id before the run directory exists, so `run_task` gained an optional `run_id` and a `new_run_id` helper. Stdout and stderr of the detached child go to a launcher log outside the run directory. Retention keeps the newest 10 runs and deletes only runs whose last upload log line is `upload: done`. `status` treats a dead pid or a heartbeat older than 5 minutes as interrupted; on Windows it checks the pid with OpenProcess, because `os.kill(pid, 0)` would kill the process there. The CLI writes nothing into the run directory, to keep blind evaluation intact.

## 2026-11-06 observation: review found a forgeable upload marker and early stop of `status` and `logs --follow`

Sandbox-derived text can reach `run.log`, so a forged `upload: done` line could make a run with a failed upload deletable; the fix considers only the last upload line. A residual case, where the process dies before uploading, is accepted. Separately, `logs --follow` and `status` stopped at the final status before the upload finished; both now follow through the upload with a 10 minute grace.
