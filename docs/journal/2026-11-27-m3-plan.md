# 2026-11-27 M3 plan

## 2026-11-27 decision: M3 is narrowed to fixes, one gpt-5.4 run per development benchmark and one or two generality tests

On 2026-11-26, after the order of work recorded in `2026-11-26-m2-close-out.md`, the owner narrowed M3 in chat (given in Polish, recorded here in English) to the fixes, one run of each of the five development benchmarks on gpt-5.4 and one or two generality tests on gpt-5.4, and said that this is enough. ADR-0010 records this with status Proposed: apart from this scope, with gpt-5.4 as the campaign model, its points and the plan's decisions D1-D9 await the owner's approval.

## 2026-11-27 observation: what preparing the plan showed in the M2 records and the code

Of the $2.63 billed for all gpt-5.4 usage, $1.81 was output tokens, $0.38 cached input and $0.45 uncached input (items are rounded), so pricing cached tokens (carry-over 7) corrects the tracked cost and the cost cap but does not change the bill. Tool results were already capped at 8,000 bytes and old ones trimmed above 200,000 characters; read from the code and not measured, once past that limit the trimming rewrites an old message before almost every call, which would break the cached prefix (whether this happened in the gpt-5.4 run is not checked). The force function-object knowledge note already described the "Could not find rho" failure before the runs that failed on it, so the plan adds a deterministic check instead of another note.

## 2026-11-27 obstacle: independent review found serious errors in the first draft of the M3 plan

All were fixed before the pull request: the campaign script would have put the benchmark id into the run id (against blind evaluation), the generality rules allowed fixing the code or replacing a task that the pipeline could not handle, and a statement about what a $6 per-run cap guarantees was false. The first rules for the force function-object check would also have dropped real defects and rejected valid cases (from `cfd-reviewer`'s reading of the OpenFOAM v2512 sources, not run). `code-reviewer` and `cfd-reviewer` each returned `changes` twice, then `approve`.
