## 2026-10-30 decision: CaseSpec schema and Planner design (Task 14, PR #43)

The CaseSpec schema is strict: every field required, no maps, no tuples, no `$ref` siblings. The Planner runs in two phases (a calculator tool loop, then one structured call), and `plan_gate` validates the result. A gate failure caused only by exceeding resources is recorded as a failed result without retry (design 6.8). Only identifier-shaped backtick spans in the task count as requested outputs. `wedge_angle_deg` was added to CaseSpec. Conventions fixed for the Planner and Geometry prompts: 2D cases have z out of plane and an `empty` boundary; axisymmetric cases have the axis along x, are symmetric about the x-y plane, and use two planar wedge patches. The CFD reviewer verified in OpenFOAM v2512 that a single patch holding both wedge faces fails with "Wedge patch is not planar".

## 2026-10-30 observation: exact boundary-name equality made the Geometry stage unsatisfiable (Task 15, PR #44)

The first host manifest check required patch names to equal the plan's boundary names. For defective plans (a 2D plan without an `empty` boundary, an axisymmetric plan listing the axis as a boundary) no geometry script could pass. The fix exempts structural patches (`empty`, wedge) and adds Planner-side boundary-name checks (non-empty, valid identifier pattern, unique). The cost: a boundary lumped into another patch is no longer caught at the geometry stage, so later gates must compare plan names with mesh patches. The prompt also states that CadQuery `rect` and `box` are centred by default.
