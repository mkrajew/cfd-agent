# 2026-11-26 M2 close-out

## 2026-11-26 decision: M2 is closed as a partial result

The owner decided in chat on 2026-11-26 (given in Polish, translated here): "We now close M2 as a partial result and move to M3. In M3 we start with the fixes we have to implement. Then we run all these benchmarks once each on a better model. Only after that do we move on to further tests." As relayed, the better model is gpt-5.4 and "all these benchmarks" are the 5 development benchmarks. The design section 12 criterion (pipe and cylinder at Re 20 and Re 100 pass) and the D8 rule were not met (pipe and both cylinder benchmarks 0 of 3 passes each, see `2026-11-25-m2-task-19-acceptance-series.md`); plan Task 7 (generality test set content, decision D5) was not done in M2 and moves to M3.

## 2026-11-26 observation: gpt-5.4 billed far below its tracked cost

Cost Management shows $2.63 for all gpt-5.4 usage in the resource group (the 2026-11-25 comparison run and its small smoke calls), while the run record tracked $6.0034 for the run alone, so its $6 cost cap fired at less than half of the cap in billed terms; this supersedes the statement in `2026-11-25-m2-stronger-model-comparison-run.md` that the real bill had not been checked. The billed output cost matches the run's 120k output tokens, and the billed input amounts, taken with the $2.50 per 1M list price, imply that about 89 % of the 1.68M input tokens were billed as cached. For gpt-oss-120b the bill ($8.52) is $0.43 above the sum of the run records of its live runs ($8.09, without the scripted replay), so the tracked figure is not an upper bound for this model. On 2026-11-22 to 11-24 the daily Foundry bill matched the run records, and on 11-25, without the other models, it was about $0.01 above them. Most of the gap falls on 2026-11-10 (billed $0.98, records $0.60), the day of the blank-reply probe (estimated at $0.32 in its journal), whose calls have no run record; that the probe explains it is an inference.

## 2026-11-26 observation: a few runs hold most of the blobs

The `runs` container holds 325,815 blobs (29.2 GB) under 84 run prefixes; the median run has 118 files, but four runs hold 30,845 to 96,382 files each, about 87 % of all blobs, and in the largest, two `solver_runner` attempt directories hold 91,720 files (file names not inspected). The storage account's cost ($1.71) is almost entirely write operations; that these four runs caused most of them is an inference, because writes were not measured per run.

## 2026-11-26 milestone: M2 closed as a partial result

Built and merged in M2: time-series helpers; calibration of the four remaining development benchmarks with hand-written, LLM-free solutions that pass the Scorer; generality-set storage and run guard (no content); in-place repair behind `repair_mode`; directive check messages and a turn budget; curated knowledge notes; cross-stage fix loops; the Solver Runner convergence gate; the CaseSpec Reynolds check and OOM handling; the Critic; the Scorer after the Critic; the VM refresh and scripted replay; the live development series. The end-to-end check was the acceptance series, in which 3 of 15 runs passed the Scorer (all `cavity-re100`), and the M2 done criterion was not met. The package version was raised to 0.2.0 in this close-out; the `v0.2.0` tag is to be created after the close-out PR is merged (the plan reserves the tag for the owner's approval, D10). The input for the M3 plan is `docs/design/m3-carryover-from-m2.md`.
