# v0.2.0: M2 robustness and full benchmark set (partial result)

M2 was closed on 2026-11-26 as a **partial result**. Its goal, a pass for the pipe and for both cylinder cases (at least 1 of 3 unchanged runs each), was **not met**.

## Results of the acceptance series

One frozen build (image `ghcr.io/mkrajew/cfd-agent:sha-901dcf8`), `gpt-oss-120b` with medium reasoning effort, `--repair-mode in_place`, default run limits. 3 runs per benchmark (n = 3), 15 runs. "Passed" means compared **with reference data** by the deterministic Scorer, which the agents cannot read.

| Benchmark | Completed | Passed the Scorer |
|---|---|---|
| Lid-driven cavity, Re 100 | 3 of 3 | **3 of 3** |
| Lid-driven cavity, Re 1000 | 1 of 3 | 0 of 3 |
| Pipe, Re 500 | 0 of 3 | 0 of 3 |
| Cylinder, Re 20 | 0 of 3 | 0 of 3 |
| Cylinder, Re 100 | 0 of 3 | 0 of 3 |

- 3 of 15 runs passed. The completed Re 1000 run failed the comparison (maximum errors 0.072 and 0.069 against a threshold of 0.05).
- The runs that did not complete were not scored. One of them stopped on an internal error before any Case Setup attempt, because the plan check had accepted an unsupported solver.
- The Critic disagreed with the Scorer in 2 of 4 completed runs (one success on a failed result, one "partial" on a passed result). Do not read a Critic verdict as validation. A result without reference data is assessed by physical checks only.
- Tracked model cost of the series: $1.93 (run records at list prices). A first attempt, lost because the VM disk filled up, is excluded. A change to the VM set-up script was merged while the series ran; all 15 run records show the same image and prompt versions.
- n = 3 per benchmark and one model: observations, not success rates. The agents can search the OpenFOAM tutorials, some of which are close relatives of the benchmarks.
- Prompts, notes and checks were developed against live runs of these same five benchmarks (as general rules), so the passes are not evidence about unseen tasks.

## What is new since v0.1.0

- Repair of failed attempts from their own files (`--repair-mode in_place`; the default is still `fresh`).
- Cross-stage fix loops with numbered passes and a budget of 10 per run.
- A convergence gate in the Solver Runner, with steadiness and periodicity checks.
- A Critic agent with bounded send-backs; the Scorer runs after its verdict is final and records whether they agree.
- Curated knowledge notes, searched before the OpenFOAM tutorials.
- More directive gate messages, a check of the stated Reynolds number, further plan, geometry and mesh checks, and one resource-reduction retry for the Planner.
- Hand-written, LLM-free solutions of the four other development benchmarks that pass the Scorer, so each benchmark is shown to be solvable with the project's tools. The cylinder Re 20 drag reference was changed with the owner's approval.
- A storage layout and run guard for the generality test set.
- `--max-cost-usd`, and a price entry for gpt-5.4 for comparison runs.

## One comparison run on a stronger model

In one `gpt-5.4` pipe run (not part of the acceptance series) the stages up to the Solver Runner passed on the first attempt. The run **failed** on its $6 cost cap in the Analyst. The cap applies to the tracked cost, which prices cached input at the full rate; all gpt-5.4 usage in the project resource group (this run and small test calls) was billed at $2.63. Evaluated outside the pipeline with a hand-written post-processing script, its solution passed the Scorer. This is n = 1 on a different image from the earlier runs it could be compared with, and it is not a result of the agent pipeline.
